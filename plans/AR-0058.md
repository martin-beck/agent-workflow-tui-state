# AR-0058: Windows GUI and PySide6 parity

Define the supported Windows GUI implementation and packaging path, using
PySide6 where it improves native windowing, accessibility, input handling, or
terminal-independent operation. The GUI must present the same Markdown design
and work-plan documents, decision highlights, batch selection, proposal
editing, clarification semantics, saved/unsaved status, exit confirmation,
and revision-bound Coordinator/AWG request and response contract as the TUI.

Acceptance criteria:

- A Windows GUI can attach to `launch_pending`, `attached`, and
  `awaiting_response` sessions and reports detached/resolved state without
  losing or duplicating a response.
- PySide6 versions, platform support, signing/packaging expectations, and
  offline development/test setup are pinned and documented.
- GUI and TUI scenario fixtures assert equivalent decision outputs, including
  user-authored proposals, clarification, batch decisions, stale responses,
  and safe exit.
- Packaging and launch failures are visible and fail closed; no credentials,
  private paths, raw prompts, or transcripts are bundled or persisted.
