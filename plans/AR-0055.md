# AR-0055: Windows TUI runtime parity

Validate and, where necessary, adapt the live TUI for supported Windows
terminal hosts. Cover keyboard input (including arrows, paging, editing and
function keys), fixed-pane layout and resize, Unicode fallback, Markdown
rendering, terminal restoration, and redacted final output. The same
revision-bound Coordinator/AWG request and response contract must be used;
Windows-specific code must not create a second decision protocol.

Acceptance criteria:

- A documented supported Windows terminal matrix is tested in CI or through a
  deterministic emulation layer.
- All decision, proposal-editing, scrolling, resize, exit-confirmation, and
  clean-terminal behaviors have parity coverage.
- Unsupported terminal capabilities fail with a user-readable diagnostic and
  never silently lose a decision or response.
- No private paths, raw transcripts, or credentials are recorded in artifacts.
